# Settlement Q&A Agent (PS-8)

A complete evidence-bound settlement tracing prototype for support agents.

## Architecture

```text
Flutter UI
   |
   | HTTP/JSON
   v
FastAPI
   |
   +--> Trace Engine -> gateway_logs.csv
   |                -> bank_settlements.csv
   |                -> ledger_entries.csv
   |
   +--> Reasoner -> deterministic rules (default)
                  -> Groq (optional)
                  -> Gemini (optional)
```

The system joins records by `transaction_id`, uses the shared status vocabulary `settled`, `delayed`, `failed`, `mismatched`, `unknown`, calculates confidence, and never silently removes missing/conflicting evidence.

## Run

### Backend

```bash
cd settlement-qa-agent/backend
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows:
# .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload
```

### Frontend

In a second terminal:

```bash
cd settlement-qa-agent/frontend
flutter pub get
flutter run
```

For a device/emulator, use `--dart-define=BACKEND_URL=...` as described in `frontend/README.md`.

## Mock data

`backend/mock_data/generate_data.py` generates ~500 deterministic transactions.

| Scenario | Gateway | Bank | Ledger | Outcome |
|---|---|---|---|---|
| Fully settled | captured | settled | posted | settled |
| T+2 delay | captured | pending | pending | delayed |
| Ledger late | captured | settled | pending | delayed |
| Amount mismatch | captured | settled | mismatched | mismatched |
| Gateway failure | failed | absent | absent | failed |
| Bank rejection | captured | rejected | pending | failed |
| Refund/reversal | refunded | settled | reversal/posted | settled/delayed |
| Ambiguous | one source intentionally absent | incomplete | incomplete | unknown + exceptions |

The bundled CSVs are generated by the same script, and the backend regenerates them if they are missing.

## API

- `GET /health`
- `GET /transactions?date_from=&date_to=&status=&merchant_id=&page=&page_size=`
- `GET /trace/{transaction_id}`
- `POST /trace/query` with `{"transaction_id":"TXN100000"}` or `{"date":"2026-03-12"}`
- `GET /analytics/summary`

## LLM

Default is zero-key deterministic mode:

```env
LLM_PROVIDER=none
LLM_API_KEY=
```

Optional:

```env
LLM_PROVIDER=groq
LLM_API_KEY=your_key
LLM_MODEL=llama-3.3-70b-versatile
```

or:

```env
LLM_PROVIDER=gemini
LLM_API_KEY=your_key
LLM_MODEL=gemini-2.0-flash
```

LLM failures automatically fall back to deterministic reasoning. Exceptions remain independently computed from source data.

## Demo flow

1. Search a transaction.
2. Show Gateway → Bank → Ledger evidence.
3. Show the computed status and confidence.
4. Open raw fields.
5. Explain the result in plain English.
6. Call out every exception.
7. Open analytics to show operational patterns.
